
=== PAGE 1 ===
D&D SIMULATOR — APPLICATION UI IMPLEMENTATION INSTRUCTIONS
ROLE
Act as the lead desktop UI architect and implementation engineer for the D&D Simulator project.
Your job is to recreate the approved Version 1 interface as a functional desktop application UI while keeping 
the entire visual system modular enough to support multiple themes later.
The selected Version 1 concept image is the primary visual reference for layout, proportions, density, 
information hierarchy, and overall user experience.
The initial theme is High Fantasy.
Future themes must include:
1. High Fantasy
2. Old Scroll
3. Modern
4. Dark Fantasy
5. Additional custom themes added later without rebuilding the interface
Do not copy copyrighted Old School RuneScape artwork, icons, textures, logos, or exact interface assets. 
The interface may have a classic compact fantasy-RPG and OSRS-inspired structure, but all assets and 
styling must be original.
==================================================
1. CORE UI OBJECTIVE
=== PAGE 2 ===
==================================================
Build a desktop interface that feels like a complete fantasy adventure control center.
The player must be able to access the following systems directly from the main screen:
- Character profile
- Health and resources
- Inventory
- Equipment
- Skills
- Quests
- Objectives
- Map
- Journal
- Recent events
- NPC information
- Relationships
- Spellbook or abilities
- Game settings
- Save and load controls
- Main narrative interaction area
The player should not need to open multiple separate windows for ordinary play.
The main screen must feel dense and useful without feeling disorganized.
=== PAGE 3 ===
The application must visually resemble the approved Version 1 layout:
- Large narrative and interaction area on the left and center
- Persistent utility sidebar on the right
- Character summary across the upper-left area
- Location and world information across the upper-center area
- Map at the top of the right sidebar
- Skills and inventory visible or one click away
- Quest and objective information visible in the central area
- Event log and navigation controls along the bottom

18. MULTI-THEME ARCHITECTURE
==================================================
This requirement is mandatory.
=== PAGE 24 ===
The interface must be built so future themes can be applied without rebuilding layouts or rewriting widget 
logic.
Separate the following layers:
1. Application logic
2. Widget structure
3. Layout geometry
4. Theme tokens
5. Theme-specific QSS
6. Theme-specific assets
7. Campaign artwork
8. User preferences
No widget should contain hard-coded theme colors, textures, fonts, border images, or decorative icons 
unless unavoidable.
Use semantic object names and dynamic properties.
Examples:
- objectName="playerSummaryPanel"
- objectName="narrativePanel"
- objectName="inventorySlot"
- property("state") = "selected"
- property("rarity") = "rare"
- property("messageType") = "quest_update"
- property("resourceType") = "health"
=== PAGE 25 ===
The stylesheet should target those semantic names and properties.
