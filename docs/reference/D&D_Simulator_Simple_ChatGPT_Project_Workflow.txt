D&D Simulator - Simple ChatGPT Project 
Workflow
A one-step-at-a-time build sequence for creating the desktop application without losing 
scope or continuity
Project role: Implementation guide for a local, persistent, single-player text adventure using LM Studio.
CORE PRINCIPLE
The application remembers and validates. The LLM interprets, narrates, and 
proposes.
Purpose
Use this workflow to build the project with ChatGPT in small, reviewable steps. Complete and test one step before 
moving to the next. The workflow assumes the project also contains the Main instructions, Adventure Reference Guide, 
and LM Studio Application Architecture and Setup Guide.
Rule for every session: Tell ChatGPT the current step number. Do not ask it to build the whole application in one 
response. Require a working deliverable, tests, and a single clearly stated next step.
Project working method
1. Open the project documents. Provide or link the four authoritative documents.
2. State the current step. Example: “Work only on Step 3 - Database schema.”
3. Let ChatGPT inspect before editing. It should read the current repository structure and relevant files first.
4. Request one complete deliverable. A module, migration, panel, test group, or integration path that can be 
run.
5. Run and verify. Use the provided commands and report errors back with complete logs.
6. Record completion. Mark the step complete only when acceptance checks pass.
7. Continue deliberately. Ask ChatGPT to begin the next numbered step; do not skip ahead.

Simple rules that prevent project drift
 Never build more than one workflow step at a time.
 Never let the LLM become the permanent owner of inventory, quests, statistics, or world state.
 Never parse database changes out of ordinary narration.
 Never send the full campaign transcript when a bounded snapshot and retrieval will work.
 Never call the LLM merely to display a factual panel.
 Never commit a partial turn when one required state operation fails validation.
 Never add advanced features before save/load and replay are reliable.
 Keep a changelog and migration for every saved-data schema change.
 End every ChatGPT work session with the exact next step.
